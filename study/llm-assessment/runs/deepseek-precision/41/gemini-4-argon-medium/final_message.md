In `modules/organization/logging.tf`, `resource "google_logging_organization_settings" "default"` configures organization-level Cloud Logging settings (such as `disable_default_sink` and `storage_location`), which requires organization-level logging permissions (`roles/logging.configWriter` / `logging.settings.update`).

Within `modules/organization`, organization-level IAM roles (including permissions for the principal running Terraform or relevant service agents) are granted via `google_organization_iam_binding.authoritative`, `google_organization_iam_binding.bindings`, and `google_organization_iam_member.bindings`. Other organization-level resources in the module—including `google_logging_organization_sink.sink` in the same `logging.tf` file, `google_org_policy_policy.default`, `google_tags_tag_key.default`, `google_essential_contacts_contact.contact`, `google_privileged_access_manager_entitlement.default`, and `google_scc_management_organization_security_health_analytics_custom_module.scc_organization_custom_module`—explicitly declare `depends_on` on these IAM binding resources so that role grants take effect before attempting to configure the organization resources.

`google_logging_organization_settings.default` only references `var.logging_settings`, `local.organization_id_numeric`, and `local.ctx.locations`, and lacks an explicit `depends_on` on `google_organization_iam_binding.authoritative`. Consequently, Terraform can attempt to create/update `google_logging_organization_settings.default` before the required organization-level IAM bindings have been applied.
