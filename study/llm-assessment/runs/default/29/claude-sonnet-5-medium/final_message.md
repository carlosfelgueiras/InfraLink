The official Google documentation and Terraform provider examples explicitly state that the Compute Engine API must be enabled on the service project before `google_compute_shared_vpc_service_project` can attach it (the API call `enableXpnResource` requires it, failing with a confusing 404 otherwise). In the module's `shared-vpc.tf`, the `shared_vpc_service` resource (lines 106-111) has no `depends_on` and no attribute reference to `google_project_service.project_services`, unlike its sibling resources (`shared_vpc_host`, `service_projects`) which do declare this dependency. Since `service_project = local.project.project_id` doesn't encode any ordering information about API enablement, Terraform has no way to infer that the project's APIs must be enabled first — it could race the `google_project_service` enablement.
