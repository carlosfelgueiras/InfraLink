In `terraform/layer2-k8s/eks-elk.tf`, `helm_release.elk` deploys the ELK Helm chart with values (`local.elk_elasticsearch_values`, `local.elk_kibana_values`, `local.elk_filebeat_values`, `local.elk_apm_values`, and `local.elk_metricbeat_values`) that mount the Kubernetes secret `elastic-certificates` by literal string name (`secretName: elastic-certificates`).

The secret itself is created by `kubernetes_secret.elasticsearch_certificates` in the same namespace (`module.elk_namespace[count.index].name`), using TLS certificates generated by `module.elastic_tls`. However, `helm_release.elk` neither references `kubernetes_secret.elasticsearch_certificates` (such as via `kubernetes_secret.elasticsearch_certificates[count.index].metadata[0].name`) nor declares it in `depends_on`.

Because `helm_release` waits for deployed resources to become ready by default (`wait = true`), and the pods created by the chart require the `elastic-certificates` secret volume to mount and start, `kubernetes_secret.elasticsearch_certificates` must exist before `helm_release.elk` is applied. Therefore, the missing dependency report is accurate.
