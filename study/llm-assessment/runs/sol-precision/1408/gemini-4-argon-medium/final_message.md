In `modules/webhook/direct/webhook.tf`, `aws_lambda_function.webhook` references `aws_iam_role.webhook_lambda.arn` for its execution role and conditionally configures `vpc_config` using `var.config.lambda_subnet_ids` and `var.config.lambda_security_group_ids`. Meanwhile, `aws_iam_role_policy_attachment.webhook_vpc_execution_role` attaches the `AWSLambdaVPCAccessExecutionRole` policy to `aws_iam_role.webhook_lambda` when `length(var.config.lambda_subnet_ids) > 0`.

When a Lambda function is configured with VPC access (`vpc_config`), AWS Lambda validates and uses the execution role's EC2 network-interface permissions (`ec2:CreateNetworkInterface`, `ec2:DescribeNetworkInterfaces`, `ec2:DeleteNetworkInterface`) during function creation and destruction to provision and clean up Hyperplane ENIs. Because `aws_lambda_function.webhook` only depends on `aws_iam_role.webhook_lambda` and has no implicit or explicit dependency on `aws_iam_role_policy_attachment.webhook_vpc_execution_role`, Terraform can attempt to create the Lambda function before the VPC access policy is attached (or detach the policy before the Lambda function is destroyed), causing creation or deletion failures.
