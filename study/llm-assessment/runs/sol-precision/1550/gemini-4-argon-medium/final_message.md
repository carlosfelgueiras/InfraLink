1. **Pre-existing default resources and adoption semantics**: In AWS, each region has a pre-existing default VPC and default subnets (one per Availability Zone). In the Terraform AWS provider, `aws_default_vpc` and `aws_default_subnet` do not provision new infrastructure under normal operation; instead, they adopt the existing default VPC and default subnets into Terraform state so their settings (such as `map_public_ip_on_launch = false`) can be managed. Because there is only one default VPC per region, filtering `data.aws_subnets.default` by `default-for-az = [true]` already uniquely identifies the region's default subnets without needing `aws_default_vpc.default.id`.
2. **Terraform `for_each` plan-time requirement**: The output of `data.aws_subnets.default` is used directly in `for_each = toset(data.aws_subnets.default.ids)` on `data.aws_subnet.default`, which in turn drives `for_each = data.aws_subnet.default` on `resource.aws_default_subnet.default`. If `data.aws_subnets.default` depended on `aws_default_vpc.default` (either via `depends_on` or by referencing `aws_default_vpc.default.id` in a `filter` block), Terraform would defer reading `data.aws_subnets.default` until the apply phase whenever `aws_default_vpc.default` is not yet in state. That would make `data.aws_subnets.default.ids` unknown during planning and cause `terraform plan` to fail with an invalid `for_each` error.
